# 第10讲 基于思考发话法的评价

两人一组相互体验对方的作品，使用思考发话法（Think-Aloud Protocol）发现改进点。

## 本讲目标

- 理解并实践思考发话法
- 让其他学员体验自己的作品，从用户的视角获得反馈
- 根据发现的问题制定改进计划

## 需要准备的物品

| 物品 | 说明 |
|---------|------|
| 自己的作品 | 事先做到能发声、能用传感器操作的状态 |
| 笔记本・书写工具 | 用于观察记录 |
| 作品说明表 | 上一讲制作的那份 |

---

## 什么是思考发话法

### 概要

**思考发话法（Think-Aloud Protocol）** 是可用性评价的代表性方法之一。让体验者在使用作品的同时，**把脑中所想的内容原样说出来**，从而发现直觉性的反应与困惑之处。

### 为什么使用思考发话法

| 通常的反馈 | 思考发话法 |
|-------------------|----------|
| 体验后询问感想 | 体验中实时听取思考 |
| 依赖记忆，有时不够准确 | 能获得那一瞬间的坦率反应 |
| 容易变成「挺好的」这类含糊回答 | 能了解到「这是什么？」这样具体的反应 |
| 有时会忘记问题点 | 能了解到操作迷茫的瞬间 |

::: tip 思考发话法的优点
- 即使人数很少（1〜2 人）也能获得有用的反馈
- 能具体地发现作品的「难以理解之处」
- 能找到制作者没有察觉的问题或趣味
:::

## 实施步骤

### 角色分工

- **评价者（体验的人）**: 一边体验对方的作品，一边把所想的说出来
- **观察者（制作者）**: 观察评价者的发言・行动・表情，并做记录

### 步骤

#### 1. 准备（2分钟）

1. 布置好作品（micro:bit 的连接、Pd 补丁的启动）
2. 把标签和作品说明表 **放到看不见的地方**（最初不加说明就让对方体验）
3. 在手边准备好观察记录表

::: warning 重要：最初不要说明
在思考发话法中，最初不说明操作方法。目的是确认「不加说明能传达到什么程度」。只有当评价者完全陷入僵局时，才给出最低限度的提示。
:::

#### 2. 思考发话法的说明（1分钟）

观察者向评价者作如下请求。

> 「接下来请你体验我的作品。体验过程中，请 **把脑中所想的内容原样说出来**。例如『这是什么？』『碰了这里声音变了』『接下来这样试试』等等，把想到的直接说成话就帮大忙了。」

#### 3. 体验与观察（5分钟）

**评价者要做的:**
- 自由地接触作品
- 持续把所想的说出来
- 说出「现在打算做什么」「发生了什么」「有什么感受」

**观察者要做的:**
- 记录评价者的 **发言内容**
- 观察评价者的 **表情**（微笑、困惑、惊讶等）
- 记录评价者 **操作迷茫的场面**
- 若持续沉默，就催促「现在在想什么呢？」
- 评价者完全陷入僵局时，给出最低限度的提示

::: tip 催促（prompting）的用语示例
- 「现在在想什么呢？」
- 「打算做什么呢？」
- 「刚才的操作发生了什么？」
- 「有什么在意的地方吗？」
:::

#### 4. 体验后的访谈（3分钟）

体验结束后，提出以下问题。

1. **整体印象** --- 「体验下来感觉如何？」
2. **有趣之处** --- 「特别觉得有趣的部分是哪里？」
3. **难以理解之处** --- 「有没有操作上感到迷茫的部分？」
4. **改进的创意** --- 「有没有觉得『这样的话会更有趣』的地方？」

#### 5. 角色互换

评价者与观察者互换，重复同样的步骤。

### 模板

```
思考发话法 观察记录表
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【评价者姓名】
【作品名】
【日期时间】

■ 体验中的记录

| 时间 | 评价者的行动 | 评价者的发言 | 表情・反应 |
|------|------------|------------|----------|
| 0:30 | 拿起了 micro:bit | 「是要动这个吗？」 | 略有困惑 |
| 1:00 | 左右倾斜 | 「哦，声音变了！」 | 惊讶・微笑 |
| 1:30 | 用手遮住 | 「弄暗的话…啊，变成别的声音了」 | 感兴趣 |
| 2:00 | 在找按钮 | 「还能做点别的吗…」 | 探索中 |

■ 好的地方・有趣的地方



■ 难以理解的地方・操作迷茫的地方



■ 改进的创意（来自评价者）



━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 记录的要点

### 分类整理

把记录的内容分为以下 3 类。

#### 好的地方

- 说出「有趣！」的场面
- 出现微笑或惊讶反应的场面
- 能够凭直觉操作的场面

#### 难以理解的地方

- 说出「这是什么？」的场面
- 不知道操作方法而停下来的场面
- 做出与意图不符的操作的场面
- 「咦？」感到困惑的场面

#### 改进的创意

- 评价者提出的创意
- 从观察中察觉到的改进可能性
- 「这样做也许能传达得更好」的灵光一现

---

## 改进计划的制定

### 问题的优先排序

按以下基准给发现的问题排定优先顺序。

| 优先度 | 基准 | 例 |
|-------|------|-----|
| **高** | 完全不知道操作方法 | 传感器的用法不够直观 |
| **高** | 作品的概念传达不到 | 不知道在表现什么 |
| **中** | 能操作但仍有改进余地 | 声音的变化再大一些会更好 |
| **中** | 可以提升体验的满意度 | 追加效果器会更好 |
| **低** | 细微的调整 | 音量平衡的微调 |

### 改进方案的列举

针对各个问题，思考技术上可以实现的改进方案。

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
改进计划表
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

问题1:（例: 倾斜了但声音的变化很小）
  优先度: 高
  改进方案: 扩大传感器数值的映射范围
  在 Pd 中的对应: 用 [* 3] 把传感器数值放大 3 倍

问题2:（例: 不知道在表现什么）
  优先度: 高
  改进方案: 在背景中追加环境音（浪声）
  在 Pd 中的对应: 用 [readsf~] 循环播放浪声的文件

问题3:（例: 不知道按钮的功能）
  优先度: 中
  改进方案: 按下按钮时用 LED 改变显示
  在 micro:bit 中的对应: 按下按钮 A 时更换图标

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

:::
