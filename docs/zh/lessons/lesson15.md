# 第15讲 最终报告会

以演示的形式发表作品的制作过程与评价结果。

## 本讲目标

- 用演示发表作品与调查结果
- 有逻辑地传达概念・技术构成・评价结果・考察
- 聆听其他学员的发表，参与问答

## 需要准备的物品

| 物品 | 说明 |
|---------|------|
| 演示幻灯片 | Google 幻灯片 / PowerPoint |
| 作品的演示视频 | 录下操作情形的视频 |
| 分析结果的图表 | SD 法剖面图、UEQ-S 的图表 |

---

## 演示的构成

按以下 5 个部分来组织发表吧。

### 1. 作品的介绍

**要传达的内容:**
- **作品名**
- **概念** --- 想表现什么
- **主题（motif）** --- 题材或主旨是什么
- **交互** --- 通过什么样的操作让声音变化

**幻灯片示例:**

```
┌──────────────────────────────────┐
│                                  │
│     作品名:「海中漫步」            │
│                                  │
│  概念:                            │
│  用声音体验深海世界的作品。        │
│  micro:bit 的倾斜会改变水深，      │
│  光的量会改变气泡的声音。          │
│                                  │
│     [作品的照片 or 插图]           │
│                                  │
└──────────────────────────────────┘
```

::: tip 活用演示视频
用视频展示实际操作的情形，发表会变得格外好懂。请准备 30 秒〜1 分钟左右的短视频。用智能手机拍摄就足够了。
:::

### 2. 技术构成

**要传达的内容:**
- 使用的传感器的种类与作用
- Pd 补丁的构成（主要的对象）
- 数据的流向（输入 → 处理 → 输出）

**幻灯片示例:**

```
┌──────────────────────────────────┐
│                                  │
│     技术构成                      │
│                                  │
│  [输入]         [处理]    [输出]  │
│  加速度Y轴 ──→ osc~  ──→ dac~   │
│  亮度     ──→ noise~ ──→        │
│  按钮A    ──→ 模式切换           │
│                                  │
│  主要的 Pd 对象:                  │
│  osc~, noise~, lop~, bp~,       │
│  delwrite~, delread~, line~     │
│                                  │
└──────────────────────────────────┘
```

::: tip Pd 补丁的截图
把 Pd 补丁的截图贴到幻灯片上，技术构成会更容易传达。补丁复杂的话，就把主要的部分放大展示。
:::

### 3. 评价结果

**要传达的内容:**
- SD 法的剖面图（折线图）
- UEQ-S 的分数（实用性品质 / 感性品质）
- 自由填写的主要评论

**SD 法的图表:**
- 把上一讲制作的折线图放大显示
- 用箭头或高亮强调特别值得关注的项目

**UEQ-S 的图表:**
- 用柱状图显示实用性品质（PQ）与感性品质（HQ）的分数
- 展示与基准的比较结果

**自由填写:**
- 引用 2〜3 条代表性的评论
- 积极与消极的都要提及

### 4. 考察

**要传达的内容:**
- 预期的印象与实际评价的比较
- UX 的实用性品质与感性品质的平衡
- 成功之处与应当改进之处
- 与思考发话法所获反馈的关联

**考察的构成示例:**

```
【意图与结果的比较】
- 所追求的印象: ○○
- SD 法的结果: △△ → 大致符合意图 / 与设想不同

【UX 的评价】
- 实用性品质: □□ → 关于操作的易懂程度
- 感性品质: ◇◇ → 关于趣味性与刺激感

【改进点】
- 如果要进一步改良的话...
```

### 5. 总结与感想

**要传达的内容:**
- 通过制作学到的东西
- 在技术方面成长的地方
- 今后想加以运用的内容
- 整体的感想

## 幻灯片制作的要点

### 1 张幻灯片 1 个信息

1 张幻灯片要传达的内容 **只放 1 个**。

| 不好的例子 | 好的例子 |
|-------|-------|
| 把概念、技术构成、评价结果都塞进 1 张 | 概念 1 张、技术构成 1 张、评价结果 1 张 |

### 图表要大，标签要易读

- 图表要以幻灯片 **一半以上** 的尺寸显示
- 轴标签与数据标签要做到 **从后排座位也能看清的大小**
- 颜色控制在 3 种以内
- 给重要的数据点加上箭头或注释

::: warning 制作图表时的注意事项
- 恰当地设定纵轴的范围（SD 法为 1〜7，UEQ-S 为 -3〜3）
- 不要让横轴的标签重叠（必要时使用换行或简称）
- 务必加上图表标题
:::

### 演示视频的准备

1. 用智能手机 **横向** 拍摄操作作品的情形
2. 视频的长度控制在 **30 秒〜1 分钟**
3. 拍摄以下内容:
   - 基本的操作（传感器的活动方式）
   - 能看出声音变化的场面
   - 有趣的操作或有特色的场面
4. 把视频嵌入幻灯片，或在发表时播放

::: tip 为视频无法播放做好准备
根据投影仪或电脑的环境，有时视频无法播放。把视频的截图也放进幻灯片会更安心。
:::

## 发表时间的参考

| 项目 | 时间 |
|------|------|
| **发表** | 5〜7分钟 |
| **问答** | 2〜3分钟 |
| **合计** | 约10分钟 |

::: warning 时间管理
请严格遵守发表时间。建议事先进行彩排并计时。特别是要把演示视频的播放时间也算进去一起练习。
:::

## 问答的要点

### 接受提问时

- 如果没听懂问题的内容，就 **反问确认**
- 老实回答「不知道」也没关系
- 对技术性的问题要具体地回答
- 收到改进建议时，就以「谢谢」来接受

### 提问时

对别人的发表，试着提出以下这类问题吧。

| 问题的种类 | 例 |
|----------|-----|
| 关于概念 | 「选择这个主题的契机是什么？」 |
| 关于技术 | 「这个声音是用哪个 Pd 对象做出来的？」 |
| 关于评价 | 「UEQ-S 的结果中有没有出乎意料的地方？」 |
| 关于制作过程 | 「制作中最费劲的地方是什么？」 |
| 关于发展 | 「如果今后要进一步发展，会追加什么？」 |

::: tip 为了提出好问题
一边听发表，一边把在意的地方或觉得有趣的地方记下来。提问对发表者来说也是学习的机会。请积极参与问答。
:::
